# PC 호스트 프로그램 기반 온보딩 제안

| 항목 | 내용 |
| --- | --- |
| 상태 | 아이디어 검증 및 제품 설계 초안 |
| 작성일 | 2026-09-25 |
| 대상 | Windows PC용 호스트 프로그램, Android PC Control 앱 |

## 1. 목표

현재 PC 연결 온보딩에서는 사용자가 PC IP, Windows 사용자 이름, SSH 포트를 입력하고, 앱 공개키를 Windows 설정 스크립트에 붙여 넣은 뒤 SSH 호스트 키를 확인한다. PC 켜기를 설정할 때는 PC MAC 주소와 공유기 정보도 직접 입력한다.

목표는 **PC 연결에 필요한 정보를 PC가 수집하고, 휴대폰에는 선택 또는 QR 스캔만 요구하는 것**이다. PC 연결을 완료한 뒤 PC 켜기와 다른 네트워크 연결은 기존처럼 선택 단계로 둔다.

이 문서는 기존 모바일 온보딩 명세를 대체하는 확정 구현 명세가 아니다. PC 측 구성과 두 페어링 경로를 결정하기 위한 제안이다.

## 2. 핵심 결정

GitHub Pages 정적 페이지 대신, Sunshine과 비슷하게 **Windows에 호스트 프로그램을 설치하고 브라우저에서 로컬 설정 화면을 여는 방식**을 채택한다.

```text
Windows PC
├─ PC Control 호스트 프로그램
│  ├─ PC/SSH 정보 수집
│  ├─ OpenSSH 준비 및 공개키 등록
│  ├─ 같은 네트워크에 서비스 알림
│  └─ 일회성 페어링 API
└─ 브라우저 설정 화면: http://localhost:<설정 포트>

Android 앱
├─ 같은 네트워크의 PC 자동 검색
├─ 검색 실패 시 PC 화면의 QR 스캔
├─ 앱 전용 SSH 공개키 전달
└─ 호스트 키 및 실제 SSH 연결 검증
```

브라우저는 설정 화면이다. 운영체제 정보 조회와 관리자 권한이 필요한 설정은 설치된 호스트 프로그램이 수행한다. 외부 웹 서버나 계정은 기본 페어링에 필요하지 않다.

## 3. 사용자 흐름

### 3.1 PC 준비

1. 사용자가 제어할 PC에 호스트 프로그램을 설치한다.
2. 프로그램이 브라우저에서 로컬 설정 화면을 연다.
3. 프로그램이 OpenSSH 상태를 점검하고 필요한 설정을 안내하거나 수행한다. 관리자 권한이 필요한 변경은 그 시점에 승인을 받는다.
4. 프로그램이 연결 가능한 네트워크 주소, SSH 포트, 선택한 Windows 계정, SSH 호스트 키 지문을 확인한다. PC 켜기용 유선 네트워크 어댑터의 MAC 주소는 후보로 보여주고 사용자가 확인한다.
5. 설정 화면에 **휴대폰에서 PC 찾기** 안내와 **QR 코드**를 함께 표시한다.

최초 설치 전에는 전용 서비스 검색을 기대할 수 없다. 따라서 PC 프로그램 설치가 두 경로의 공통 선행 단계다.

### 3.2 기본 경로: 같은 네트워크에서 자동 검색

1. 앱이 PC Control 호스트 서비스를 검색한다. 구현 후보는 Android `NsdManager`와 mDNS/DNS-SD다.
2. 발견한 PC의 이름과 주소를 보여준다. 여러 대면 사용자가 한 대를 선택한다.
3. 앱이 페어링 요청과 앱 전용 SSH 공개키를 PC 호스트 프로그램에 보낸다.
4. PC 설정 화면에 요청한 휴대폰과 확인 코드를 표시한다. 사용자가 PC에서 승인한다.
5. 호스트 프로그램이 공개키를 해당 Windows 계정의 올바른 `authorized_keys` 위치에 등록한다.
6. 앱이 PC에서 받은 SSH 호스트 키를 검증하고 `hostname` 같은 무해한 명령으로 인증을 시험한다.
7. 성공하면 PC 연결 정보를 저장한다.

서비스 알림을 계속 제공하려면 호스트 프로그램이 로그인 후 또는 부팅 후 실행되어야 한다. 백그라운드 상주 여부와 수명 주기는 구현 단계에서 결정한다. 페어링 후 전원 제어는 현재의 SSH 경로를 유지할 수 있다.

### 3.3 대체 경로: PC 화면의 QR 스캔

자동 검색이 실패하면 앱이 **PC 화면의 QR 스캔**을 제안한다. 호스트 프로그램이 QR에 다음 정보를 담는다.

| 항목 | 용도 |
| --- | --- |
| 프로토콜 버전과 PC 식별자 | 앱과 호스트 프로그램의 호환성 확인 |
| 연결 후보 주소와 페어링 포트 | 검색 없이 PC에 직접 연결 |
| SSH 포트와 대상 Windows 계정 | 수동 입력 대체 |
| SSH 호스트 키 지문 | 첫 연결에서 PC 신원 대조 |
| 짧은 유효기간의 일회성 요청 정보 | 해당 페어링 시도에 요청 연결 |
| 선택된 유선 어댑터 MAC 주소 | PC 켜기 단계의 입력 후보 |

앱은 QR을 읽은 뒤 **검색 경로와 동일한 페어링 요청·PC 승인·공개키 등록·SSH 검증**을 수행한다. 따라서 QR은 단순 설정값 가져오기로 끝나지 않는다.

QR은 많은 정보를 직접 담을 수 있다. 짧은 숫자 코드는 그 자체로 이 정보를 담기 어렵다. 코드만으로 두 기기를 연결하려면 조회할 로컬 서비스 또는 별도 중계 서버가 필요하다. 이 설계에서는 **QR을 정보 전달 수단**, **양쪽 화면의 코드를 사용자 확인 수단**으로 사용한다.

### 3.4 실패와 복구

| 상황 | 앱에서 제공할 경로 |
| --- | --- |
| PC가 검색되지 않음 | QR 스캔으로 이동 |
| QR을 읽었지만 PC에 접속할 수 없음 | 같은 LAN/VPN 여부, 방화벽, 게스트 Wi-Fi 격리 상태 안내 |
| PC 승인 요청이 만료됨 | PC 화면에서 새 QR 발급 후 재시도 |
| SSH 호스트 키가 QR 정보와 다름 | 연결 중단 및 PC 화면 정보 재확인 |
| 공개키 등록 또는 SSH 인증 실패 | 호스트 프로그램의 진단 결과를 보여주고 재시도 |
| 카메라를 사용할 수 없음 | QR 내용 대신 주소·확인 정보 입력 경로 제공 |

QR은 mDNS 검색이 막힌 상황을 해결할 수 있지만, 휴대폰에서 PC로 향하는 통신 자체가 차단된 상황을 해결하지는 못한다. 그 경우 별도 VPN 또는 네트워크 설정이 필요하다.

## 4. 자동 수집 가능한 값과 남는 설정

| 현재 입력값 | 호스트 프로그램을 통한 처리 | 주의점 |
| --- | --- | --- |
| PC IP 주소 | 사용 가능한 주소를 수집하고 앱에 전달 | VPN·가상 어댑터를 제외하거나 후보를 표시해야 함. DHCP 변경도 고려 |
| PC SSH 포트 | `sshd` 설정과 실제 리스닝 상태 확인 | 기본값 22로 단정하지 않음 |
| Windows 사용자 이름 | 실제로 사용할 계정을 사용자가 PC에서 선택 | 관리자 계정과 일반 계정의 키 파일 위치가 다름 |
| 앱 SSH 공개키 | 페어링 요청으로 전달해 PC에서 승인 후 등록 | 앱 개인키는 PC로 전송하지 않음 |
| PC SSH 호스트 키 지문 | PC에서 직접 읽어 QR 또는 페어링 응답으로 전달 | 앱이 실제 SSH 연결의 지문과 비교 |
| PC MAC 주소 | WOL에 적합한 유선 어댑터를 후보로 제시 | 여러 NIC 중 사용자가 확인해야 할 수 있음 |
| 공유기 주소 | 기본 게이트웨이를 후보로 제시 | 기본 게이트웨이가 SSH/WOL 대상이라는 보장은 없음 |
| 공유기 SSH 사용자·포트·WOL 인터페이스 | 자동 수집 불가 | 공유기별 설정 단계로 남김 |
| OpenVPN 프로필 | 기존 Android 앱에서 선택 | PC 호스트 프로그램이 대신 만들지 않음 |

PC 연결의 수동 입력은 대부분 제거할 수 있다. **PC 켜기와 외부 접속까지 완전 자동화되는 것은 아니다.** 현재 제품은 공유기에 SSH로 접속해 `ether-wake`를 실행하며, OpenVPN for Android의 기존 프로필을 사용한다.

## 5. 보안 및 운영 원칙

- 브라우저 설정 화면은 기본적으로 PC의 `localhost`에서만 연다. 휴대폰용 페어링 API는 필요한 LAN 주소에만 열고, Windows 방화벽 범위를 Private 네트워크와 필요한 로컬 대역으로 제한한다.
- 페어링 요청은 짧게 만료되고 한 번만 사용할 수 있어야 한다. PC 화면의 명시적 승인, 요청한 휴대폰의 식별 정보 표시, 실패 횟수 제한을 둔다.
- 확인 코드만 맞으면 무조건 공개키를 등록하는 방식은 피한다. 승인할 요청과 공개키 지문을 PC 화면에 연결해 표시한다.
- 앱의 SSH 개인키는 기존처럼 Android 기기에 남긴다. PC에는 공개키만 등록한다.
- 앱은 QR 또는 승인된 로컬 경로로 받은 PC 호스트 키 지문과 실제 SSH 연결 지문을 비교한다. 불일치하면 자동 승인하지 않는다.
- QR에는 비밀번호, VPN 자격 증명, SSH 개인키를 넣지 않는다. 일회성 정보는 만료와 재사용 방지 대상으로 취급한다.
- PC를 인터넷에 직접 노출하거나 SSH 방화벽을 전체 인터넷으로 넓히지 않는다. 외부 제어는 기존 VPN 경로를 사용한다.

## 6. 현재 코드와의 관계

| 현재 구성 | 활용 또는 변경 방향 |
| --- | --- |
| `scripts/setup-windows-ssh.ps1` | OpenSSH 설치·서비스·방화벽·공개키 등록 로직의 출발점. 호스트 프로그램에 통합 또는 설치 단계에서 호출 |
| `apps/mobile/src/components/OnboardingScreen.tsx` | PC 주소·계정 수동 입력 앞에 자동 검색과 QR 분기를 배치하고, 공통 검증 단계로 합류 |
| `packages/capacitor-pc-control` | Android 서비스 검색, QR 스캔 연동, 페어링 통신을 위한 네이티브 API 추가 |
| 기존 SSH identity와 host-key pinning | 유지. 새 페어링 과정이 제공한 지문을 실제 연결과 대조 |
| PC 켜기·OpenVPN 단계 | PC 연결 성공 이후의 선택 단계로 유지 |

현재 저장소에는 Windows 상주 호스트 프로그램이나 QR 기반 페어링 프로토콜이 없다. 이 문서는 구현 완료를 뜻하지 않는다.

## 7. 권장 구현 순서와 검증 기준

1. **PC 호스트 프로그램 최소 버전:** 로컬 브라우저 UI, PC/SSH 정보 표시, 계정 선택, 기존 Windows SSH 설정 기능 통합.
2. **QR 경로:** QR 생성·스캔, PC 승인, 앱 공개키 등록, 호스트 키 대조, 무해한 SSH 명령까지 실기기에서 완료.
3. **자동 검색 경로:** mDNS/DNS-SD 검색을 추가하고 QR 경로와 같은 페어링 프로토콜을 사용.
4. **복구와 운영:** 여러 네트워크 어댑터, 주소 변경, 재페어링·해제, 방화벽, 설치·업데이트·제거 흐름 점검.

첫 검증 목표는 다음과 같다.

> 새 Windows PC와 Android 기기에서 사용자가 PC IP·Windows 사용자 이름·SSH 포트·공개키를 휴대폰에 직접 입력하지 않고, 자동 검색 또는 QR 스캔으로 PC 연결을 완료한다. 앱은 실제 SSH 인증에 성공하고 잘못된 호스트 키는 거부한다.
